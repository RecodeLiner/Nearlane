# Nearlane

Независимый нативный клиент для совместимости с Quick Share. **Исследовательский
прототип: экспериментальный вход через браузер реализован; подтверждены
выдача разрешения Quick Share и обмен сертификатами. В проверенной сессии получено
9 сертификатов, из них 6 активных, без отклонённых записей. Поиск своих устройств
по Wi-Fi LAN реализован. Передача в обе стороны проверена на файле 94 байта.
На ПК также получено и открыто отправленное с Android изображение размером 91 458 байт.
Файловый движок также проверяется отдельной командой.**
Проект не связан с Google или Samsung. Название и оформление собственные.

Цель проекта - обмен с Android без режима «Для всех» и без передачи приложению
master token Google-аккаунта. Проект реализует передачу в режиме «Свои устройства».
Режим «Контакты» пока не реализован.

## Разработка на NixOS

```sh
nix develop
cargo test --locked --workspace --exclude nearlane-slint
cargo run -p nearlane-cli -- status
cargo run -p nearlane-slint
```

Нативный пакет (когда изменяете файлы, добавляйте новые в Git, чтобы flake их видел):

```sh
NIXPKGS_ALLOW_UNFREE=1 nix build --impure
./result/bin/nearlane-slint
```

Общие зависимости требуют Rust 1.88 или новее, настольное приложение - Rust 1.95 или новее. Сборка и запуск на Windows и macOS локально не проверены.

## Настольное приложение

Общий `crates/application` владеет состоянием приложения, фоновыми задачами,
настройками, запуском входа, Bluetooth и обработкой решений из уведомлений.
Интерфейс получает снимки состояния и отправляет типизированные команды.
Токены, URL авторизации, ключи и адреса участников в снимки не входят.
Фоновая работа не зависит от таймеров отрисовки или видимости окна.

`apps/slint` содержит интерфейс отправки, приёма и настроек на Slint Material.
Приложение использует системный трей и поддерживает русский и английский языки.

Оригинальный код остаётся MIT OR Apache-2.0. Material-компоненты имеют MIT-лицензию.
Для фреймворка Slint выбрана Royalty-free 2.0 с обязательным указанием Slint в
окне «О Nearlane». Nix относит эту лицензию к несвободным, поэтому в команде
сборки указано `NIXPKGS_ALLOW_UNFREE=1`. Лицензии включены в пакет.

Настройки сохраняются атомарно в `preferences.json` в каталоге
конфигурации приложения (`~/.config/nearlane` на Linux). Старый Linux-файл
`~/.config/Nearlane/Nearlane.conf` переносится при первом запуске, оригинал
сохраняется. Перенос старых настроек Qt из macOS/Windows пока не реализован.
OAuth-конфигурация и токен в системном кошельке от этого переноса не меняются.

Slint проверяется без окон командой `nearlane-slint --smoke-test`; она использует
временные синтетические данные, без Google-аккаунта и радио. Пример снимка:
`nearlane-slint --preview /tmp/nearlane.png --language ru --page settings`.
Результаты обмена с Android и границы аппаратных проверок описаны ниже.

## Пакеты и кэширование

```text
crates/core       - типы предметной области; без зависимостей
crates/auth       - OAuth/PKCE, проверка callback, безопасная диагностика
crates/certificates - работа с ключами и сертификатами Quick Share без сети
crates/discovery  - ограниченный поиск Wi-Fi LAN и распознавание своих объявлений
crates/account    - callback, HTTPS/gRPC, временная регистрация своих устройств
crates/protocol   - UKEY2/D2D, ограниченные кадры Nearby и подмножество protobuf
crates/transfer   - потоковое сохранение файлов, ограничения, локальный тест
crates/platform   - системное хранилище, уведомления и адаптеры Bluetooth
crates/service    - состояние приложения, проверка возможностей и приватности
crates/application - общий фоновый контроллер, команды, снимки, локализация
crates/application/i18n - общие каталоги переводов: русский и английский
apps/cli          - диагностика из терминала
apps/slint        - интерфейс Slint Material 3
docs/research     - проверяемые результаты исследования
tools             - автономные инструменты анализа
work              - локальные данные, зависимости и бинарники, НЕ в Git
third_party/beto  - опубликованные Apache-2.0 компоненты Google для UKEY2
```

Для Java-разработчика: Cargo workspace похож на Gradle multi-project build,
а каждый crate - отдельная единица компиляции. `cargo test -p nearlane-auth`
собирает только пакет авторизации и его зависимости. Cargo кэширует результаты
компиляции в `target/`. Изменение страницы Slint требует пересборки приложения,
скомпилированный протокол сохраняется в кэше.
`Cargo.lock` и `flake.lock` фиксируются в Git. Release-профиль использует thin LTO;
для быстрых итераций используйте обычный dev-профиль.

## Исследование авторизации

Интерфейс следует рекомендациям [material-skill](https://github.com/gdlbo/material-skill):
**Отправить**, **Получить**, **Настройки**; в узком окне навигация находится снизу.
Используются компоненты Slint Material со светлой и тёмной палитрами.
Состояние учётной записи и сертификаты доступны в диагностике настроек.
Файл можно выбрать через Ctrl+O (⌘O на macOS), разделы - через Alt+1, Alt+2 и Alt+3.

Язык выбирается в **Настройки → Язык**: системный, русский или English. Выбор
сохраняется и применяется сразу, включая статусы и новые уведомления, без
перезапуска приложения и текущей передачи. Для остальных системных языков
используется английский. Имена устройств, файлов и пути не переводятся.

Переводы хранятся в `crates/application/i18n/nearlane_{en,ru}.ts`.
Slint вызывает `I18n.tr(...)` для строк в контексте `Ui`. Контроллер на Rust
читает встроенный русский каталог и переводит отложенные шаблоны `Text` в контексте
`Backend`. Имена и пути подставляются после перевода.
После добавления строк выполните `python3 tools/update_translations.py`, заполните
новые переводы и запустите `python3 tools/update_translations.py --check`.
Подробнее - [локализация](docs/LOCALIZATION.md).

В интерфейсе появилась кнопка **Войти через Google** в разделе «Настройки → Google-аккаунт». Это локальный эксперимент
совместимости без регистрации отдельного OAuth-приложения.
Браузер показывает страницу Google; Nearlane не получает пароль, cookies или
master token. На странице согласия может отображаться имя официального Quick
Share, поскольку эксперимент использует его локальные desktop-параметры.

При установке через flake пакет содержит приложение и локальный импортёр:

```sh
nearlane-import-google-oauth /путь/к/NearbyShareExe
nearlane-slint
```

При запуске из репозитория импортёр доступен напрямую:

```sh
python3 tools/import_google_oauth.py /путь/к/NearbyShareExe
./result/bin/nearlane-slint
```

Импорт проверяет точный SHA-256 изученной версии EXE, не запускает её и не
выводит значения параметров. Произвольный установщик или другая версия не принимаются.
На NixOS/Linux конфигурация сохраняется в
`$XDG_CONFIG_HOME/nearlane/oauth-client.json`, обычно
`~/.config/nearlane/oauth-client.json`. На macOS используется
`~/Library/Application Support/Nearlane/oauth-client.json`, на Windows -
`%APPDATA%/Nearlane/oauth-client.json`. На Unix новый каталог имеет права `0700`,
файл - `0600`. Существующий файл импортёр не перезаписывает.

Готовый JSON можно выбрать в **Настройки → Google-аккаунт → Выбрать конфигурацию
входа**. Проверенные параметры копируются в постоянное локальное место; исходный
файл не изменяется. При следующем запуске копия загружается автоматически,
независимо от текущей папки и наличия исходного JSON. Ошибка импорта сохраняет
предыдущую рабочую конфигурацию. Смена конфигурации доступна после выхода из
аккаунта и завершения текущих операций. Путь и результат импорта видны в настройках.

Формат JSON: `client_id` и необязательный `client_secret` на верхнем уровне.
Если указан `scope`, он должен совпадать с разрешением Nearby. Пароли и токены
аккаунта в этот файл не импортируются. Refresh token хранится отдельно в системном
кошельке; access token остаётся в памяти.

`NEARLANE_OAUTH_CONFIG` задаёт абсолютный runtime-путь вместо стандартного и для
приложения, и для импортёра. У импортёра также есть `--output /абсолютный/путь.json`.
Для нестандартного `--output` приложение нужно запустить с тем же путём через
`NEARLANE_OAUTH_CONFIG`. Значения кредов не передаются через переменные окружения.
Публичный пакет не содержит конфигурации Google. Файл нельзя включать в Nix-выражение
или помещать в `/nix/store`; приложение читает его только во время запуска.

При обновлении с прежней версии достаточно один раз выбрать существующий
`work/private/oauth-client.json` через UI. Сохранённый в кошельке вход подхватится
для того же OAuth-клиента. Автоматического копирования файлов из текущей папки нет.

Для эксперимента используйте отдельный тестовый аккаунт. Авторизация происходит
только после нажатия кнопки. Отмена закрывает текущую попытку, поздний ответ не
восстанавливает сессию. Access token и ключи устройств остаются в памяти.
Refresh token сохраняется в системном кошельке (Secret Service на Linux,
Keychain на macOS, Credential Manager на Windows), без файлового обходного
варианта. После одного входа приложение восстанавливает сеанс при запуске и
обновляет доступ до истечения срока. Если кошелёк заблокирован или недоступен,
приложение сообщает об этом. **Выйти из аккаунта** сбрасывает состояние обмена,
отменяет незавершённый вход, удаляет локальную и сохранённую сессию и отправляет запрос очистки
сертификатов именно этой временной регистрации. Не закрывайте окно, пока идёт
очистка. Её фактическая семантика на сервере пока не проверена; при ошибке или
закрытии приложения сертификаты могут остаться до истечения срока (до 9 дней
плюс 2 часа). Браузерные cookies и
разрешение в Google остаются; отзыв доступа ко всему OAuth-проекту - отдельная
операция, которая не подменяет обычный выход. Закрытие окна сохраняет вход;
для проверки восстановления не нажимайте **Выйти из аккаунта** перед перезапуском.

После обновления потребуется один вход с согласием на offline access: прежняя
версия не сохраняла refresh token. Дождитесь сообщения **Sign-in is remembered**,
закройте и откройте приложение. При сетевой ошибке сохранённый вход остаётся;
**Повторить вход** повторяет восстановление. Отозванный Google refresh token
не используется дальше: потребуется новый вход.

Сохранённый вход также содержит идентификатор этой регистрации компьютера.
При восстановлении он повторно используется, но ключи и сертификаты создаются
заново. После явного выхода следующий вход создаёт другую регистрацию.

Режим «Контакты» пока не реализован. Приватный приём от своих устройств
включается после успешного обмена сертификатами, если он разрешён в настройках. Локальное хранение desktop-параметров
не означает, что Google разрешил их использование независимым приложением;
подробнее - в [заметках о лицензиях](docs/LICENSING.md).

### Проверка своих сертификатов

Перезапустите собранное приложение и войдите через браузер. После выдачи разрешения
Nearlane автоматически создаст временные ключи компьютера,
опубликует три сертификата только для своего аккаунта и загрузит доступные
сертификаты своих устройств. Пароли, master token и регистрация собственного
OAuth-приложения для этого эксперимента не требуются.

В разделе **Настройки → Показать диагностику** появятся **This device is registered** и количество сертификатов.
Ноль сертификатов - допустимый ответ сервера, но он ещё не позволяет найти
телефон. При ошибке отображается безопасное описание либо числовой gRPC-код;
**Повторить настройку устройств** повторяет запрос с теми же ключами и именем регистрации.
Для отчёта достаточно текста этой панели, без токенов и URL входа.

Обмен с API подтверждён: 9 сертификатов, 6 активных, 0 malformed.
Обмен с API сам по себе не доказывает личность соседнего устройства: при передаче
выполняется живая взаимная проверка ключей.
Режим «Для всех» не используется. Подробности и границы подтверждённого -
в [исследовании Identity API](docs/research/identity-certificates.md).

### Поиск телефона без публичной видимости

После подготовки сертификатов устройства появляются в разделе **Отправить**.
Кнопка **Обновить** запускает дополнительный поиск на 20 секунд. Остановка
поиска доступна в диагностике; постоянный поиск переключается в настройках.
ПК и телефон должны находиться в одной локальной сети. На телефоне используйте
тот же аккаунт и видимость Quick Share для своих устройств. Если телефон найден
только по Bluetooth и ожидает Wi-Fi, разблокируйте его экран. Режим «Для всех» не требуется и приложением не используется.

Файлы передаются по Wi-Fi LAN. Bluetooth используется для подсказок обнаружения;
сама подсказка без Wi-Fi-адреса не позволяет отправить файл. Приложение
сопоставляет объявления с сертификатами аккаунта и показывает имя только из
успешно расшифрованных метаданных. Открытое сетевое имя не используется как
доказательство. Устройства в списке - кандидаты: живая проверка их ключей
выполняется при отправке.

### Проба отправки на телефон

В разделе **Отправить** нажмите **Выбрать файл**, выберите небольшой файл и
нажмите **Отправить** в строке телефона. За одну передачу поддерживается один обычный файл
до 64 ГиБ, без папок и возобновления. На Unix ссылки на исходный файл не
открываются. Результат поиска пригоден для подключения 120 секунд; при истечении
выполните поиск ещё раз. Телефон должен оставаться в той же сети, с включённым
Quick Share и приватной видимостью. Bluetooth-обнаружение телефона с погашенным
экраном проверено; Wi-Fi-адрес в текущей проверке появляется после разблокировки.
Отправка на заблокированный телефон пока не подтверждена. Специальный экран
«Получить» не требуется и может временно делать
телефон видимым всем.

Приложение устанавливает Nearby-соединение, проверяет обе paired-key подписи,
дожидается принятия предложения телефоном и только после этого передаёт содержимое.
Успех показывается после ACK именно файлового payload от проверенного участника.
Если ACK потерян, файл уже может быть на телефоне; автоматического повтора нет.
Телефоны с версией возможностей 4 могут не присылать этот дополнительный ACK:
после ограниченного ожидания результат остаётся неподтверждённым. Это не мешает
проверять ключи и передавать файл, но по одним записям в сокет нельзя утверждать,
что Android сохранил его.
При отказе приватной проверки публичный обход не используется. **Отменить**
прерывает сетевой ввод-вывод; выход из аккаунта также останавливает передачу.

Это экспериментальная реализация Wi-Fi LAN. На реальном Android проверена
приватная передача небольшого `.txt`: файл получен и открывается. Полная
совместимость, большие файлы на Android и отправка на телефон с погашенным экраном
ещё не подтверждены. Для диагностики достаточно безопасного
текста ошибки с `stage`, без токенов, дампов трафика и URL входа.

Тот же механизм доступен из терминала. Закройте приложение, чтобы две копии
не меняли ключи одной регистрации одновременно. Команда использует только
уже сохранённый вход, не открывает браузер, не выбирает похожие имена и
не включает публичную видимость:

```sh
./result/bin/nearlane send-own --device "Точное имя телефона" /путь/к/файлу.txt
```

### Большие файлы и macOS

Лимит отправки, приёма и уведомлений - 64 ГиБ на файл. Данные обрабатываются
при отправке порциями по 64 КиБ. После проверки устройства и согласия на приём
разрешены зашифрованные кадры размером до 1 МиБ вместе с заголовками протокола,
без четырёхбайтового префикса длины. Активная передача больше не обрывается через три минуты;
остаются ограничения на зависший кадр, отсутствие файлового прогресса и полное
время операции. Проверены 513 МиБ на собственных локальных участниках; большие
файлы на Android ещё требуют проверки. Папки и возобновление пока не поддерживаются.

Общий Rust-код переносим, Bluetooth-сканер использует btleplug в платформенном слое. Darwin
Nix-сборка создаёт `Applications/Nearlane.app` с разрешением Bluetooth. Реальной
проверки на Mac пока не было. Отправка произвольного сигнала обнаружения через
публичный CoreBluetooth ограничена, поэтому этот адаптер пока есть только для
Linux; Wi-Fi-передача от него не зависит.

### Приём файлов на ПК

После запуска, восстановления входа и подготовки приватных ключей приём
включается автоматически. На телефоне отправьте файл через Quick Share на
**Nearlane**. По умолчанию файлы от подтверждённых устройств своего аккаунта
принимаются автоматически, как в оригинальном Quick Share.

В разделе **Настройки** есть сохраняемые параметры:
**Принимать от своих устройств** (по умолчанию включён) и
**Спрашивать перед получением** (по умолчанию выключен).
С подтверждением доступны **Accept / Decline** прямо в уведомлении Linux/KDE;
если система не поддерживает действия, уведомление открывает раздел «Получить»
с кнопками **Принять / Отклонить**.
Автоприём не обходит проверку сертификата и взаимных приватных доказательств.

Поддерживается один файл до 64 ГиБ. Существующие файлы не перезаписываются.
Папка по умолчанию - системная папка загрузок с подпапкой `Nearlane`
(`~/Downloads/Nearlane` при стандартных настройках). Она создаётся при включении
приёма. Чтобы выбрать другую папку, откройте **Получить**, остановите приём,
нажмите **Изменить папку** и включите приём снова.
После принятого файла приём готовится к следующему, пока не нажаты
**Остановить приём**, **Выйти из приложения** или выход из аккаунта. Остановка приёма сохраняется
на следующий запуск; завершение приложения и выход из аккаунта не стирают настройки.
Перед исходящей передачей не занятый входящим соединением приёмник временно
останавливается, затем возобновляется. Одновременная передача в обе стороны
пока не поддерживается. Папка назначения также сохраняется между запусками.

Используется TCP 7364 и mDNS. В текущем NixOS эти правила уже есть; системные
настройки не менялись. Другой Quick Share-приёмник может занимать этот порт.
Подтверждены обнаружение ПК на Android и успешное сохранение файла
с телефона. Локальные тесты приёмника также проходят.

### Фоновая работа

После входа настольное приложение постоянно ищет устройства своего аккаунта.
Переключатель **Искать устройства в фоне** в настройках останавливает или возобновляет
поиск. Ушедшие и устаревшие объявления удаляются, свой ПК исключён из списка.
BLE-обнаружение использует Rust-адаптер btleplug. На Linux есть тихий сигнал обнаружения
при открытом разделе «Отправить»; передача остаётся по Wi-Fi. Поиск в фоне можно
выключить тем же переключателем. Подробности и ограничения macOS -
в [заметках Bluetooth](docs/research/bluetooth.md).

Крестик прячет окно в системный трей, если он доступен. Значок открывает окно;
в меню доступны приём, постоянный поиск и **Выйти из приложения**. При успешном сохранении
показывается уведомление. При включённом подтверждении входящее уведомление
Linux содержит имя проверенного устройства, имя файла, размер и кнопки решения.
Если трея нет, закрытие
окна завершает приложение. Автозапуск при входе в систему пока не устанавливается.

На NixOS/KDE проверены папка по умолчанию, наличие трея, скрытие/возврат окна
и вызов уведомления. Непрерывный поиск проверен появлением и удалением собственного
синтетического объявления. Bluetooth/BLE и другие ОС ещё требуют проверки.

### Какие устройства стоят за сертификатами

Включите **Настройки → Показать диагностику**. Список показывает каждую запись,
период действия и активность. Свои текущие ключи помечены **This computer**;
у сертификата, сопоставленного при поиске, появляется расшифрованное имя.
У остальных записей остаётся **Device name encrypted / not discovered**.

Три записи **This computer (Nearlane)** - нормальный комплект текущей регистрации
на последовательные периоды действия, а не три копии ПК. Удаление этого комплекта
прервёт приватную передачу. **Выйти из аккаунта** отправляет запрос очистки текущей
регистрации. В изученном Identity RPC нет отдельного удаления сертификата по его
номеру; старые регистрации с уже потерянными идентификаторами сейчас адресно
очистить не умеем. Их сертификаты истекают автоматически.

В опубликованной схеме Google указано, что ключ расшифровки имени не возвращается
в скачиваемых сертификатах. Его получают из локального объявления устройства.
Поэтому 9 сертификатов нельзя честно превратить в полный список телефонов:
одному устройству принадлежат несколько ротационных сертификатов, а неизвестные
записи не связываются с уже найденным телефоном по догадке. Список также может
содержать старые регистрации Nearlane до истечения их срока.

```sh
# Ввести URL через stdin, а не аргумент процесса или историю shell.
cargo run -p nearlane-cli -- inspect-auth-url

# Только локальное чтение PE, без запуска и сетевых запросов.
python3 tools/inspect_pe.py work/research/msi/NearbyShareExe
```

Программа анализа выводит только заранее выбранные признаки и смещения. Она не
выводит найденные client secret/токены и не генерирует дамп всех строк.
Не вставляйте секреты или полные URL авторизации в GitHub issues.

## Статус и лицензия

- Библиотечные тесты проверяют PKCE, CSRF state, строгий callback, размеры кадров
  и запрет неявного перехода к публичной видимости.
- Интерфейс показывает состояние авторизации и обнаруженные устройства.
- Проверены получение OAuth-разрешения и публикация/загрузка сертификатов.
- Код Nearlane распространяется под **MIT OR Apache-2.0**, компоненты Material - под MIT, фреймворк Slint - под Royalty-free 2.0.
- Бинарники Google не распространяются и не входят в Nix/Cargo исходники.

## Файловый движок

```sh
./result/bin/nearlane test-transfer
# либо в nix develop:
cargo run -p nearlane-cli -- test-transfer
```

Команда создаёт два собственных TCP-участника только на loopback, устанавливает
Google UKEY2/D2D, обменивается paired-key кадрами и проверяет взаимные подписи
и знание сертификатов на синтетических ключах, привязанных к этой сессии,
передаёт Quick Share introduction/acceptance и файл размером чуть больше 3 МиБ
кадрами Nearby. Получатель сохраняет файл без перезаписи существующих и отправляет
подтверждение. SHA-256 проверяется после повторного чтения сохранённого файла.
Синтетические файлы удаляются вместе с временной папкой. Аккаунт не нужен.

Использованы опубликованные Rust-компоненты Google (Apache-2.0), с неизменёнными
исходниками и закреплённой ревизией. Параметры упаковки и происхождение -
в `third_party/beto/README.md`; собственные 22 теста UKEY2 также проверены.

Команда проверяет транспортное/файловое подмножество на синтетических участниках.
Подключение к Android, обмен connection-кадрами, проверка paired-key с сертификатами
аккаунта и обработка согласия реализованы и отдельно проверены на реальном телефоне.
Локальный тест сам по себе не подтверждает совместимость с Android или режимом «Контакты».

Подробнее: [архитектура](docs/ARCHITECTURE.md), [исследование](docs/research/2026-11-14-auth.md),
[лицензии и ограничения](docs/LICENSING.md), [границы безопасности](SECURITY.md).
